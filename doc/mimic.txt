1. INTRODUCTION                                          *mimic-introduction*

mimic is designed to detect the language and project context of the current
buffer and choose the right LSP server, linter, and formatter for that project.
It is designed for LazyVim but does not require LazyVim.

The plugin follows a fill-in policy: existing configuration wins. mimic only
adds a tool when the category has no owner yet.

Phase 7 adds an in-memory evidence cache with event-driven invalidation.
Phase 6 added opt-in override mode. Detection reports the language, project
root, project evidence, existing configuration, and tool availability for the
current buffer. Resolution scores that evidence into one explainable plan per
category. The applier then fills the gaps in that plan: it starts the LSP
servers it owns and writes missing conform and nvim-lint entries. With
override enabled, it replaces a configured linter or formatter with the
resolved best external tool. Existing configuration wins unless override is
enabled.

==============================================================================
2. REQUIREMENTS                                          *mimic-requirements*

  - Neovim 0.11.3 or newer.
  - neovim/nvim-lspconfig for LSP server definitions.
  - stevearc/conform.nvim for formatting.
  - mfussenegger/nvim-lint for linting.
  - mason-org/mason.nvim for the future installer.

Java support additionally needs mfussenegger/nvim-jdtls. It is a soft
dependency. |:Mimic| status reports when it is missing.

==============================================================================
3. INSTALLATION                                          *mimic-installation*

Use lazy.nvim: >lua

  {
    "Shishir-Kc/mimic.nvim",
    event = "VeryLazy",
    dependencies = {
      "neovim/nvim-lspconfig",
      "stevearc/conform.nvim",
      "mfussenegger/nvim-lint",
      "mason-org/mason.nvim",
    },
    opts = {},
  }
<
Your plugin manager installs the four declared plugin dependencies. mimic does
not download or install language tools during setup.

Add mfussenegger/nvim-jdtls separately if you work with Java.

==============================================================================
4. SETUP                                                       *mimic.setup()*

setup() accepts a table. Every option is optional. Unknown keys are reported
once and ignored. Invalid values keep their defaults. >lua

  require("mimic").setup()
<
With no arguments, the defaults below are used: >lua

  {
    enabled = true,
    override = {
      lsp = false,
      lint = false,
      format = false,
    },
    install = { mode = "ask" },
    languages = {
      python = true,
      rust = true,
      c = true,
      cpp = true,
      java = true,
      javascript = true,
      typescript = true,
    },
    categories = {
      lsp = true,
      lint = true,
      format = true,
    },
    log_level = "warn",
  }
<
Options: ~
  enabled       boolean. Enable mimic for this configuration.
  override      boolean or table. Off by default. true enables lint and
                format. A table enables only the named categories. lsp is
                reserved and not implemented yet. See |mimic-override|.
  install.mode  "ask", "never", or "auto". The installer is not implemented
                yet. Nothing is downloaded.
  languages     Per-language switches. `c` and `cpp` are separate keys.
  categories    Per-category switches for lsp, lint, and format.
  log_level     "trace", "debug", "info", "warn", or "error".

setup() is idempotent. Calling it again without reload is a no-op.

5. COMMANDS                                                  *:Mimic* *mimic-commands*

                                                                *:Mimic-status*
:Mimic status
  Show setup state, session state including the enabled override categories,
  registry counts, cache hit and miss counts, the availability of the four
  integration points plus the optional nvim-jdtls dependency, the detection
  result for the current buffer, its resolution plan, and what mimic has
  applied, including any override and the owner it replaced.

                                                                *:Mimic-toggle*
:Mimic toggle
  Enable or disable mimic for this Neovim session. This does not change the
  configured value. Both transitions clear cached evidence. Turning off
  reverts everything mimic applied; turning on applies to loaded buffers again.

                                                                *:Mimic-reload*
:Mimic reload
  Revert everything mimic applied, clear cached evidence and session state,
  and reapply the original setup() options. Reload bypasses the double-setup
  guard.

                                                               *:Mimic-install*
:Mimic install
  Placeholder for the Phase 8 installer. It prints a notice and downloads
  nothing.

Without a subcommand, :Mimic prints the usage line.

==============================================================================
6. HEALTH                                                  *mimic-health*

Run: >vim

  :checkhealth mimic
<
The check verifies the Neovim version, whether setup() has run, which
integration points are available, whether override is enabled, whether the
registry data is valid, whether detection works for the current buffer, the
resulting plan, cache hit and miss counts, and how much the applier has changed,
including active overrides. It never installs anything.

7. REGISTRY                                                  *mimic-registry*

The registry is static data. It lists languages, filetypes, project root
markers, candidate tools, and fallback priorities. Loading it starts no LSP
clients, changes no conform or nvim-lint configuration, calls no Mason APIs,
and downloads nothing.

Candidates per language:

  Python        LSP: basedpyright, pyright
                Lint: ruff, flake8, pylint, mypy
                Format: ruff, black
  Rust          LSP: rust-analyzer
                Lint: clippy, rust-analyzer coverage
                Format: rustfmt
  C             LSP: clangd
                Lint: clang-tidy, clangd coverage
                Format: clang-format
  C++           LSP: clangd
                Lint: clang-tidy, cpplint, clangd coverage
                Format: clang-format
  Java          LSP: jdtls
                Lint: checkstyle with project config
                Format: jdtls, google-java-format
  JavaScript    LSP: ts_ls, vtsls
                Lint: eslint, biome LSP
                Format: prettier, biome, prettierd, eslint_d
  TypeScript    LSP: ts_ls, vtsls
                Lint: eslint, biome LSP
                Format: prettier, biome, prettierd, eslint_d

These are fallback priorities, not forced choices. Existing configuration and
project evidence win. Language LSPs are alternatives, so mimic will not start
both ts_ls and vtsls for the same project. Lint and format can be owned by an
LSP when it provides that capability, for example clangd with --clang-tidy or
jdtls formatting.

8. DETECTION                                                *mimic-detection*

Detection is read only and runs on demand, for example from |:Mimic-status| or
|:checkhealth|. It starts no LSP client, changes no conform or nvim-lint
configuration, calls no Mason API, and downloads nothing.

For a buffer, detection reports:

  - Language, from the buffer filetype. javascriptreact maps to javascript and
    typescriptreact maps to typescript. C and C++ stay separate.
  - Project root: the nearest directory with a registry root marker, falling
    back to .git. The matched marker is reported.
  - Project evidence: root markers present, tool config files present, package
    manager signals such as poetry.lock, Cargo.lock, compile_commands.json, or
    gradlew, and dependency names from package.json.
  - Existing configuration: active LSP clients, servers enabled or declared
    with vim.lsp, servers declared in LazyVim opts, formatters configured in
    conform, linters configured in nvim-lint, and whether LSP formatting is
    available. Each record carries source tags.
  - Tool availability: for every registry candidate, whether its executable is
    found in a project local directory, on PATH, or in the Mason package
    directory. Plugin requirements such as nvim-jdtls are checked too.

Project evidence and tool availability are cached in memory per language and
root. Existing configuration is not cached. See |mimic-cache|.

Detection records sources. Resolution classifies them and decides the fill-in.
See |mimic-resolution|. Detection ignores the entries and clients that mimic
itself applied, so a plan keeps explaining mimic's choice instead of treating
its own effect as user configuration.

==============================================================================
9. RESOLUTION                                                *mimic-resolution*

Resolution is read only and pure. It turns a detection context into a plan
with one owner per category: lsp, lint, and format. It starts no LSP client,
changes no conform or nvim-lint configuration, calls no Mason API, and
downloads nothing. The applier turns the plan into configuration.

Per category, the resolver:

  1. Gathers providers. The lsp category only considers servers whose role is
     language. lint and format consider external tools plus LSP servers that
     cover the category, but coverage only counts when that server is already
     active or enabled.
  2. Keeps an existing owner: active first, then enabled, then already
     configured, including a formatter or linter that is not in the registry.
     This is the fill-in rule.
  3. With override enabled for lint or format, and a replaceable existing
     owner, picks the best eligible tool instead. If it differs from the
     owner, the plan says override and records the previous owner. A custom or
     mixed entry is still kept, and the reason says so. See |mimic-override|.
  4. With no existing owner, scores the eligible providers and picks the best.
  5. If nothing is eligible, chooses nothing and records an install hint when
     a preferred tool is simply missing.

Scoring adds to the registry priority for the category (0 to 100):

  - Dedicated config file present: +60
  - Shared manifest present: +10
  - package.json dependency matches the tool: +25
  - Executable found project-locally: +15
  - preferred_when_configured with a dedicated config: +40
  - deprecated: -100 and ineligible

A tool is ineligible when it is not installed, is deprecated, requires a
missing plugin such as nvim-jdtls, or requires project config that is absent
such as checkstyle. Ties break by registry order, priority then tool id, so the
result is deterministic.

A config file is dedicated when few tools list it and shared when many do, for
example package.json for every JavaScript tool. This is derived from the
registry, so it stays correct as tools are added.

Existing configuration is classified by authority. Active, declared, and
runtime-enabled count as user level. A server that only appears in LazyVim
opts counts as LazyVim level. Classification is reported in the plan as the
source of the previous owner, so an override decision is explainable. Runtime
enablement is indistinguishable from user configuration, so both are user
level.

==============================================================================
10. APPLYING                                                  *mimic-applying*

The applier fills gaps by default. It acts on a resolved plan and touches a
category when the plan says select or override. When the plan says keep,
nothing changes.

Each category is handled differently:

  lsp      mimic starts only the server it owns, once per buffer, with
           vim.lsp.start and an explicit root_dir. It never calls
           vim.lsp.enable, so it never globally enables a server. A running
           client with the same name and root is reused. Servers owned by
           rustaceanvim or nvim-jdtls are deferred to those plugins. A
           table-shaped cmd is checked for a runnable executable first.
  format   When the filetype has no conform.formatters_by_ft entry, mimic
           writes the selected formatter list. When the resolved owner is an
           LSP formatter, it writes { lsp_format = "fallback" } instead. With
           override, it replaces the existing entry and records the previous
           value.
  lint     When the filetype has no nvim-lint.linters_by_ft entry, mimic
           writes the selected linter. If no nvim-lint trigger group exists,
           mimic creates one for BufReadPost, BufWritePost, and InsertLeave.
           With override, it replaces the existing entry and records the
           previous value.

conform and nvim-lint are loaded on demand, and only when mimic owns that
category. After requiring the plugin, mimic checks the filetype key again
before writing, so a setup hook that already filled the key still wins.

For Python, when mimic starts basedpyright or pyright, it sets
settings.python.pythonPath from a project .venv, venv, or virtualenv. It does
this only for clients it starts, never for servers the user manages.

Application is per buffer. setup() creates one mimic FileType autocmd and then
sweeps buffers that are already loaded, because VeryLazy fires after the first
FileType. :Mimic reload reverts everything mimic changed, clears detection
and resolution state, and applies again. :Mimic toggle off reverts; toggle on
sweeps loaded buffers. Reverting stops only clients mimic created and restores
only the conform and nvim-lint keys mimic wrote.

Applying changes no files, downloads nothing, and starts no server that mimic
did not select.

11. OVERRIDE MODE                                             *mimic-override*

Override is opt-in and off by default. It applies to lint and format only,
because conform and nvim-lint use replaceable invocation tables, so replacing
and reverting them is exact. LSP servers stay fill-in only, because
vim.lsp.enable is global while mimic decides per project, and a detached
client can reattach on the next FileType.

Enable it per category: >lua

  require("mimic").setup({
    override = { lint = true, format = true },
  })
<
The short form override = true enables lint and format. override.lsp is
reserved and not implemented yet; setting it warns and is ignored.

When override is enabled for a category that already has an owner, mimic
replaces that owner with the best eligible tool from the registry:

  - The existing owner is kept when it is already the best tool, when no
    external tool is eligible, or when the entry is custom or mixed. The
    |:Mimic-status| plan says which rule applied.
  - A custom entry is a configured formatter or linter name that no registry
    tool owns. It is never overwritten.
  - A mixed entry configures names from more than one tool. It is treated as
    custom and kept.
  - An external linter or formatter can be replaced by an LSP that already
    provides the category when that LSP scores higher. For format, mimic
    writes { lsp_format = "fallback" }, the same as a normal LSP selection.
    For lint, nvim-lint cannot express LSP coverage, so the existing owner is
    kept and the plan says the target is an LSP. Override never starts or
    stops LSP servers.

Replacing an entry records the exact previous value, including
{ lsp_format = "fallback" } options and multi-formatter lists, so
|:Mimic-reload| and |:Mimic-toggle| off restore it. Applying the same override
again without an external change is a no-op and keeps the first recorded
previous value.

Runtime enablement is indistinguishable from user configuration, so a tool
that LazyVim enabled at runtime is reported as a user-level owner.

==============================================================================
12. CACHING                                                    *mimic-cache*

Detection caches filesystem evidence only, in memory, for the current Neovim
session:

  - Project evidence per language and root: root markers, config files,
    package manager signals, and package.json dependencies.
  - Tool availability per language and root: project local binaries, PATH,
    Mason packages, and required plugin availability.

Existing configuration and resolved plans are never cached. Active LSP clients,
conform entries, nvim-lint entries, and the applier ledger are always read
fresh, so user edits and mimic's own writes are visible. Plans always explain
the current state.

The cache is bounded to 256 entries per layer. Invalidation events:

  BufWritePost, FileChangedShellPost       Project evidence
  FocusGained, VimResume, DirChanged       Both layers
  User LazyLoad, User LazyDone             Availability
  |:Mimic-reload|, |:Mimic-toggle|         Both layers and statistics

There are no OS-level filesystem watchers. An external project change made
while Neovim is focused is picked up on the next save, focus change, directory
change, or reload. A tool installed outside Neovim is picked up when focus
returns or after a reload. Cache invalidation refreshes evidence only.
Application still happens on FileType, on setup() for loaded buffers, and on
reload or toggle. Run |:Mimic-reload| to apply a changed plan to open buffers.

|:Mimic-status| reports hit, miss, and entry counts. |mimic-health| reports
per-layer statistics and the events above.

==============================================================================
13. DESIGN NOTES                                               *mimic-design*

Authority order, highest first: user explicit configuration, project signals,
plugin registry defaults, LazyVim extras. The user always wins.

One tool owns a category for a buffer. mimic never starts a second LSP server
for the same job and never adds a linter that is already provided by an active
LSP server.

Phase 7 contains the registry, read-only detection, resolution, the applier,
opt-in override mode, and the evidence cache. The installer arrives in Phase 8.
